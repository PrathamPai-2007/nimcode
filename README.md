# Nimcode

**Nimcode** is an open-source, CLI-based AI coding agent driven by NVIDIA NIM. It wraps a continuous Read-Eval-Print Loop (REPL) around a multi-model LLM architecture, giving the AI programmatic "hands" (sandboxed tools) to inspect and alter your workspace.

## Key Features

*   **Terminal Interface (TUI):** A gorgeous, responsive terminal interface powered by `prompt_toolkit` and `rich`. Enjoy inline interactive model selection, mode-colored UI frames, seamless autocomplete for slash commands, and an unobtrusive status bar.
*   **Three Operational Modes (Plan, Build & YOLO):**
    *   **Plan Mode (`/plan`):** Enforces a strict "Plan-Before-Execution" protocol. The agent must present a structured architectural `<plan>` for approval before executing any tools.
    *   **Build Mode (`/build`):** Human-in-the-loop execution. Every tool call displays a unified diff or command preview before prompting for `y/n` approval.
    *   **YOLO Mode (`/yolo` / `--yolo`):** High-speed autonomous execution. Displays full terminal previews for every action but automatically accepts tool calls without pausing for human input (capped at a default safety limit of 50 steps per turn to prevent runaway execution).
*   **Instant Mode & Model Switching:** Press `Shift+Tab` to cycle between Plan, Build, and YOLO modes directly from the prompt. Type `/model` to instantly swap NVIDIA NIM models mid-conversation—Nimcode automatically handles the context handoff via `summary.md`.
*   **Background Process Support:** Start, query, and stop long-running services and dev servers (like `npm run dev` or `python -m http.server`) detached in the background using `start_background_process`, `get_process_output`, and `stop_process` without freezing the agent.
*   **Visual Verification Loop:** Nimcode can visually verify frontend code using the `screenshot_page` tool to render local servers or HTML files via Playwright. The agent can build, run, screenshot, self-critique, and iterate on UI elements autonomously.
*   **Autonomous Web Searching:** Search the web on the fly using the built-in `web_search` tool (powered by a zero-dependency, pure-Python DuckDuckGo HTML parser) to obtain documentation, reference APIs, and error troubleshooting details.
*   **Sub-Agent Swarms:** Spawn background AI agents using the `/team` command and `spawn_agent` tools. Delegate complex sub-tasks to specialized subagents running in parallel.
*   **Extensible Skills System:** Install and manage dynamic capabilities on the fly using `/skills` and `/install-skill`.
*   **Built-in Testing & Review:** Use `/test` to instantly trigger your test suite inside the sandbox, or `/diff` and `/changes` to review uncommitted edits. Use `/recap` to get a quick 4-5 line summary of the current session generated by a lightweight model.
*   **Consolidated Workspace Architecture:** All system files, session histories, backups, and handoff summaries are stored securely inside `~/.nimcode/<project-name>/`, keeping your workspace root pristine.
*   **Live Agent Rules:** Use the `/init` command to automatically construct a robust `AGENTS.md` file. Nimcode injects these rules live on every turn, meaning updates apply immediately without restarting your session.
*   **Auto-Backups & Session Recovery:** Overwritten files are automatically snapshotted to `~/.nimcode/<project-name>/backups/`. Use `/resume` or `nimcode resume` to instantly reload and continue past conversations.

## Prerequisites

*   Python 3.10+
*   An [NVIDIA NIM API Key](https://build.nvidia.com/) (set as `NVIDIA_API_KEY`).

## Installation

1.  Clone the repository and navigate into the directory:
    ```bash
    git clone https://github.com/PrathamPai-2007/nimcode.git
    cd nimcode
    ```
2.  Install `nimcode` globally in editable mode:
    ```bash
    pip install -e .
    ```
3.  Set your NVIDIA NIM API key. You can export it to your environment, create a `.env` file in your current project directory, or create a global fallback at `~/.nimcode/.env`:
    ```env
    NVIDIA_API_KEY=nvapi-...
    ```
4.  If you want to use the agent's visual verification loop for frontend development, install Chromium for Playwright:
    ```bash
    playwright install chromium
    ```

## Configuration (`nimcode.toml`)

`nimcode` reads from an optional `nimcode.toml` file in your **current workspace root** (the directory you run the command from). All fields are optional—sensible defaults are used when the file is absent.

| Key                    | Default                         | Description                                          |
|------------------------|---------------------------------|------------------------------------------------------|
| `fast_model`           | `nvidia/nemotron-3-ultra-550b-a55b` | Model used for Build & YOLO mode execution           |
| `plan_model`           | `nvidia/nemotron-3-ultra-550b-a55b` | Model used for Plan mode reasoning                   |
| `mode`                 | `build`                         | Default startup mode (`plan`, `build`, or `yolo`)    |
| `timeout`              | `60`                            | Hard timeout (seconds) for subprocess execution      |
| `max_loop_iterations`  | `10`                            | Safety cap on consecutive AI steps per turn (overridden to 50 in YOLO mode) |
| `output_cap`           | `100000`                        | Max characters returned from any single tool output  |
| `max_tokens`           | `4096`                          | Output completion token limit for models (helps avoid silent gateway rejections on models like MiniMax-M3) |
| `auto_backup`          | `true`                          | Snapshot files before overwriting them               |
| `disable_docker`       | `false`                         | Toggle to disable Docker command sandboxing          |
| `docker_image`         | `python:3.11-slim`              | Docker image used for sandboxed command runs         |

You can switch models or modify runtime configuration settings at any time mid-session with the `/model` and `/config` commands.

## Usage

Because `nimcode` is installed globally, you can run it from **any directory** on your machine.

Check your environment and configuration:
```bash
nimcode status
```

Start a new interactive session:
```bash
nimcode
```

Run nimcode with a direct task instruction:
```bash
nimcode run "Create a Python script that fetches the current weather."
```

Run directly in YOLO Mode (auto-approves all edits and commands):
```bash
nimcode run --yolo "Refactor main.py to use async/await and run the tests."
```

Resume an interrupted session interactively:
```bash
nimcode resume
```

Resume the most recent session automatically:
```bash
nimcode resume --latest
```

Initialize or update the `AGENTS.md` rules file for the current workspace:
```bash
nimcode init
```

Check the status of active subagents:
```bash
/team
```

List available skills:
```bash
/skills
```

## Testing & CI

`nimcode` includes a comprehensive pytest suite to verify tool executions, configuration management, and subagent state:

1.  **Running Tests Locally:**
    Ensure you have `pytest` installed, then run:
    ```bash
    pytest
    ```
2.  **Continuous Integration:**
    Tests and code quality checks (via Ruff) run automatically on push or pull request to the `main` and `master` branches. See `.github/workflows/ci.yml` for workflow steps.

## Security Boundaries & Swarm Autonomy

*   **Sub-Agent Swarm Autonomy:** Background sub-agents (`spawn_agent` / `/team`) run autonomously inside threads to complete delegated work. Unlike the main REPL thread, background sub-agents execute tools directly and **do not** halt for user permission or render interactive previews.
*   **Environment Scrubbing Limits:** Environment variables containing common secret suffixes/prefixes (e.g. `API_KEY`, `TOKEN`, `SECRET`, `PASSWORD`, `_PW`, `_PWD`, `CREDENTIAL`, `PRIVATE_KEY`) are dynamically scrubbed and masked prior to command execution.
*   **Inline Parameter Scrubbing:** Command-string secrets (like `--token=<secret>`, `-p<password>`, or Bearer tokens in headers) are scrubbed via regex before being presented in the human-in-the-loop preview or returned in the execution logs.
*   **Smart Output Truncation:** Commands or tool outputs exceeding the `output_cap` are truncated intelligently (head + tail truncation). This drops the middle of the payload to ensure both the beginning context and the final crash stack traces remain visible.
